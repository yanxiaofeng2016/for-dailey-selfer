# 与规格比值雷达图结论

四组 SMT 配置的资源占用都远低于规格：最高点只有 **0.09（CPU）**，五维里真正拉开差距的是 **CPU** 和 **内存带宽**。图形整体收在右侧（CPU / 内存容量 / 内存带宽），网络和磁盘几乎贴着圆心。

## 一句话

当前负载吃不满机器规格；**SMT ON + bind node** 的占用面最大，**SMT ON 默认** 最小；内存容量四组相同，磁盘带宽比值为 0。

## 分项

| 指标 | 结论 |
| --- | --- |
| CPU | 区分度最大。SMT ON 默认最低（0.05）；SMT ON+bind 与 SMT OFF 默认并列最高（0.09）；SMT OFF+bind 为 0.08。开启 bind node 后，SMT ON 的 CPU 比值从 0.05 升到 0.09。 |
| 内存容量 | 四组都是 **0.04**，雷达图上叠成同一个点，不是配置差异。 |
| 内存带宽 | 第二区分度。SMT ON+bind 最高（0.07），SMT OFF 默认最低（0.05）。无论 SMT 开关，bind node 都把内存带宽比值抬高一档（0.06→0.07，0.05→0.06）。 |
| 网络带宽 | 四组都在 **0.004–0.008**，比 CPU / 内存大约低一个数量级，所以在 0.10 公共刻度上贴着圆心。相对最高是 SMT OFF+bind（0.008），最低是 SMT OFF 默认（0.004）。 |
| 磁盘带宽 | 四组「与规格比值」都是 **0**。原始表里 SMT OFF 默认的磁盘原始数据也是空的，这一轴目前不能用来对比。 |

## 配置对比

1. **SMT ON（默认）**  
   占用面最小：CPU 只有 0.05，内存带宽 0.06。更像“没绑核、超线程开着”时 CPU 规格吃得少。

2. **SMT ON + bind node**  
   占用面最大：CPU 0.09、内存带宽 0.07，两项都是四组里最高或并列最高。绑核后 CPU 和内存带宽都更贴近规格。

3. **SMT OFF + 默认**  
   CPU 已经到 0.09，但内存带宽最低（0.05）、网络也最低（0.004）。关超线程、不绑核时，CPU 占用上来了，内存/网络带宽反而更低。

4. **SMT OFF + bind node**  
   比较均衡：CPU 0.08，内存带宽 0.06，网络带宽四组最高（0.008）。关超线程再绑核，网络规格占用相对更明显。

## 怎么读这张图

- 比值是「实测 / 规格」，不是性能分。多边形越大，只说明相对规格用得更多，不直接等于更快。
- 五轴共用 0.00–0.10 刻度，所以网络（约 0.5%）和磁盘（0）会看起来像“没画”，数据仍在。
- 内存容量完全重合，对选型没有信息量；后续若要看瓶颈，应补磁盘带宽有效数据和业务指标（吞吐、延迟），单凭这张占用雷达不能判断哪种 SMT 配置更好。
