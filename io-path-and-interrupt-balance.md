## 二、128 个中断（均衡）vs 120 个中断（不均衡）

### 128 中断：每 CPU 一个队列，全程隔离

```
         提交侧 (CPU 上)                    HBA 侧                    完成侧 (中断回 CPU)
    ┌──────────────────┐           ┌─────────────────┐           ┌──────────────────┐
    │                  │           │                 │           │                  │
    │  CPU 0           │           │                 │           │  CPU 0           │
    │  ┌────────────┐  │  msix=0   │  Reply Queue 0  │  IRQ 0   │  ┌────────────┐  │
    │  │ blk-mq     ├──┼─────────→│  (CPU 0 专属)   ├─────────→│  │ 完成处理   │  │
    │  │ 合并→请求  │  │           │                 │           │  │            │  │
    │  └────────────┘  │           │                 │           │  └────────────┘  │
    │                  │           │                 │           │                  │
    │  CPU 1           │           │                 │           │  CPU 1           │
    │  ┌────────────┐  │  msix=1   │  Reply Queue 1  │  IRQ 1   │  ┌────────────┐  │
    │  │ blk-mq     ├──┼─────────→│  (CPU 1 专属)   ├─────────→│  │ 完成处理   │  │
    │  │ 合并→请求  │  │           │                 │           │  │            │  │
    │  └────────────┘  │           │                 │           │  └────────────┘  │
    │                  │           │                 │           │                  │
    │  ...             │           │  ...            │           │  ...             │
    │                  │           │                 │           │                  │
    │  CPU 127         │           │                 │           │  CPU 127         │
    │  ┌────────────┐  │ msix=127  │  Reply Queue 127│  IRQ 127  │  ┌────────────┐  │
    │  │ blk-mq     ├──┼─────────→│  (CPU 127专属)  ├─────────→│  │ 完成处理   │  │
    │  │ 合并→请求  │  │           │                 │           │  │            │  │
    │  └────────────┘  │           │                 │           │  └────────────┘  │
    │                  │           │                 │           │                  │
    └──────────────────┘           └─────────────────┘           └──────────────────┘

    每个 CPU 的 IO 从提交→合并→请求→HBA队列→完成中断，全程在自己的通道内
    ✅ 无跨 CPU 争用    ✅ 合并行为一致    ✅ 中断负载均匀    ✅ 无 cache 竞争
```

### 120 中断：8 个 CPU 被迫共享，路径交叉

```
         提交侧 (CPU 上)                    HBA 侧                    完成侧 (中断回 CPU)
    ┌──────────────────┐           ┌─────────────────┐           ┌──────────────────┐
    │                  │           │                 │           │                  │
    │  CPU 0           │           │                 │           │                  │
    │  ┌────────────┐  │  msix=8   │                 │           │  CPU 0           │
    │  │ blk-mq     ├──┼────┐     │  Reply Queue 8  │  IRQ 8   │  ┌────────────┐  │
    │  │ 合并→请求  │  │    ├────→│  (CPU 0+120共享)├─────────→│  │ 完成处理   │  │
    │  └────────────┘  │    │     │                 │           │  │ 2倍负载!   │  │
    │                  │    │     │  ┌───────────┐  │           │  └────────────┘  │
    │  CPU 120         │    │     │  │CPU 0 的IO │  │           │                  │
    │  ┌────────────┐  │    │     │  │CPU120的IO │  │           │  CPU 120         │
    │  │ blk-mq     ├──┼────┘     │  │混在一起!  │  │           │  ┌────────────┐  │
    │  │ 合并→请求  │  │           │  └───────────┘  │           │  │ 提交了IO   │  │
    │  └────────────┘  │           │                 │           │  │ 但完成中断 │  │
    │                  │           │                 │           │  │ 去了CPU 0! │  │
    │                  │           │                 │           │  └────────────┘  │
    │  ─ ─ ─ ─ ─ ─ ─  │           │  ─ ─ ─ ─ ─ ─ ─ │           │  ─ ─ ─ ─ ─ ─ ─  │
    │                  │           │                 │           │                  │
    │  CPU 8 (独占)    │           │                 │           │  CPU 8           │
    │  ┌────────────┐  │ msix=16   │  Reply Queue 16 │  IRQ 16  │  ┌────────────┐  │
    │  │ blk-mq     ├──┼─────────→│  (CPU 8 专属)   ├─────────→│  │ 完成处理   │  │
    │  │ 合并→请求  │  │           │                 │           │  │ 正常负载   │  │
    │  └────────────┘  │           │                 │           │  └────────────┘  │
    │                  │           │                 │           │                  │
    └──────────────────┘           └─────────────────┘           └──────────────────┘

    ❌ 问题1: CPU 0 和 CPU 120 的 IO 混入同一个 Reply Queue → IO 合并行为异常
    ❌ 问题2: Reply Queue 8 的完成中断全发到 CPU 0 → CPU 0 承担 2 倍中断负载
    ❌ 问题3: CPU 120 提交的 IO, 完成中断在 CPU 0 处理 → 跨 NUMA cache 竞争
    ❌ 问题4: 120 个独占 CPU 各处理 1 份, 8 个 CPU 各处理 2 份 → 吞吐不均衡
```

## 三、不均衡在 IO 路径中的具体影响点

```
  FIO 线程 (128个)
       │
       ▼
  ① VFS/文件系统 ──── 无影响，每线程独立生成 bio
       │
       ▼
  ② blk-mq 软件队列 ─── ⚠️ 影响点1: host_tagset 模式下 hctx 和 reply queue 关联
       │                    共享 reply queue 的 CPU 的 IO 进入同一个 hctx
       ▼
  ③ IO 合并 (merge) ─── ❌ 影响点2: 两个 CPU 访问不同磁盘的 IO 被混入同一队列
       │                    不该合并的 IO 可能被尝试合并，增加延迟
       │                    合并判断的局部性被打破
       ▼
  ④ Request 派发 ────── ⚠️ 影响点3: 共享队列的 request 数量是独占队列的 2 倍
       │                    派发延迟增加
       ▼
  ⑤ mpt3sas 驱动 ───── cpu_msix_table[cpu] 查表选 reply queue
       │                 共享 CPU 选到同一个 msix_index
       ▼
  ⑥ HBA Reply Queue ── ❌ 影响点4: 共享队列的完成中断量是独占队列的 2 倍
       │                    HBA 固件写入同一个 Reply Queue 的频率加倍
       ▼
  ⑦ MSI-X 中断 ─────── ❌ 影响点5: 中断全部路由到一个 CPU
       │                    该 CPU 的 softirq 处理量翻倍
       │                    成为整条 IO 路径的瓶颈
       ▼
  ⑧ 完成回调 ──────────  blk_mq_complete_request → 磁盘带宽体现不均衡
```

## 四、一句话总结

**120 vs 128 的本质区别不是"少 8 个中断"，而是打破了"提交 CPU = 完成 CPU"的 1:1 隔离。**

128 中断时，每个 CPU 的 IO 全程走自己的专属通道（软件队列→合并→派发→HBA 回复队列→中断），互不干扰。120 中断时，8 对 CPU 被迫共享通道，从 IO 合并到中断处理整条路径上都产生争用，最终体现为磁盘带宽不均衡。
